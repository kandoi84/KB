# Analysis and judgment design (mini spec 08, first slice)

## Intent and boundary

Produce a frozen **internal research worksheet** from reviewed direct claims, strict point-in-time metrics, and explicitly labelled analyst estimates. It must expose the current state, most-likely path, independent debates, fair-value arithmetic, uncertainty, catalyst mechanisms, and skeptical judgment. It must not turn a calculation or a human assertion into validated investment research. The output always has `publication_allowed: false`; mini specs 09 and 12 own later validation and promotion.

The full Framework describes cross-company scoring, market-implied expectations, reverse valuation, and historical calibration. This first slice does not compute those. There is no validated market price/consensus feed or model execution contract in the runtime. Price-dependent margin of safety, expectation gap, poker rank/draw, and score remain `NOT_ASSESSED`, not fabricated.

## Design choice

Use one strict, analyst-supplied JSON packet plus a deterministic validator/calculator. This follows the existing frozen-report pattern and is small enough to review. The alternative of free-form LLM analysis would hide missing evidence; a full model and scoring engine now would pretend to have data and calibration the KB lacks. A later slice can replace manual assumptions with a versioned model while retaining this worksheet as a prior frozen view.

## Input contract

`analyze-judgment` takes packet, exact frozen 05 claim-review report, project directory, identity/filing catalog, state directory, and safe run ID. The packet binds `issuer_id`, `isin`, timezone-aware `cutoff_timestamp`, `claim_review_report_id`, `analyst_id`, and `prepared_at` no later than cutoff. It names four ordered layers: `macro`, `sector`, `industry`, `company`. Each layer has a concise current-state statement, directional transmission to its child (company has a business mechanism instead), at least one cited claim ID or metric ID, and an explicit `UNKNOWN` plus reason if evidence is absent. A missing layer is blocked. The layer chain is an analyst hypothesis, not a machine-proven causal relationship.

Every cited claim must have `INTERNAL_REVIEWED` in the exact 05 report and still pass its current raw/catalog recheck. The runner must validate the report digest, safety fields, entity/cutoff, parent report IDs, and exact claim IDs. A changed raw source or catalog must block replay; rehashing a forged report cannot make a blocked claim usable. Claims may support prose, but numeric authority is the typed metric catalog.

`metric_refs` identify exact `(isin, metric_name, period_end, period_kind, reporting_scope, unit, value_kind, metric_id, filing_id, value_decimal)` leaves. The runner checks the confirmed issuer-to-ISIN catalog binding, calls `query_metrics(...)` at the packet cutoff, and demands one exact matching leaf, including identity and source validity. A missing, ambiguous, late, revised, or damaged metric blocks that numeric reference. All source-backed numeric assertions in layer/path text must be represented as metric references; because arbitrary prose cannot be proved free of numbers, the first slice uses structured numeric fields and forbids digits in free-text analytical statements except citation IDs. This is a conservative syntactic guard, not semantic validation.

`most_likely_path` has a dated horizon, operating hypothesis, named driver IDs, cited claim/metric IDs, and falsifiers. `base_fair_value` is a positive plain decimal **INR per share** with `ANALYST_ESTIMATE`, method (`DCF`, `SOTP`, `RESIDUAL_INCOME`, or `OTHER`), model snapshot ID, local model file path and SHA-256, as-of timestamp, and substantive economic rationale. The runner hashes the referenced file, enforces that its path stays inside the project, and records the hash. It does **not** verify spreadsheet formulas, cash-flow forecasts, or that the entered value came from that file. This is `MODEL_UNVERIFIED` in the report.

Each independent debate has a unique ID and driver ID, occurrence definition, probability as a decimal in `[0,1]`, incremental per-share value impact in INR, evidence refs, rationale, and falsifier. The analyst must attest that each impact is incremental to the base and not counted in another debate. Duplicate driver IDs or an explicit correlation link block the simple sum; a correlation assertion of `NONE_KNOWN` is only a human attestation. The runner calculates `probability_weighted_fair_value = base + Σ(probability × incremental_impact)` with `Decimal`, fixed output rounding, and no floating point. Negative or zero resulting value blocks. The value is an *indicative analyst estimate*, not a validated target. Price never changes the base or WACC.

`valuation_range` has low/high INR per share, method and rationale for the sensitivity, and a list of named fragility drivers (for example terminal-value share, cyclicality, leverage, model disagreement). The range must contain the calculated fair value and have nonzero width. The runner records it as an analyst uncertainty range; it does not call it statistical confidence or derive the Framework score error band. `quality_trajectory` and `valuation_fragility` are diagnostic enums with explanation and cited evidence/assumption IDs, with no new score weight.

`catalysts` identify event definition, 3–24 month date/window, probability, affected KPI, earnings link, valuation link, linked debate ID or `NO_VALUATION_DELTA`, source refs, and an explicit double-count disposition. This first slice never adds catalyst EV to fair value: a linked debate already carries the value effect, and an unlinked catalyst is a watch item. Missing mechanism or overlapping value attribution blocks that catalyst. An empty list requires a reason saying no evidenced catalyst was found.

`judgment` has: a 3–5 year inversion/premortem and falsifiers; a plain-language earnings engine with 2–3 value drivers and a catalyst→KPI→earnings→valuation chain; the nine named bias checks from the Framework, each `FLAGGED` or `CHECKED` with a concrete reason; incentive/second-order/circle-of-competence/opportunity-cost checks; a hammer check asking whether the same diagnosis would be given for every company; and explicit `NOT_ASSESSED` for price, alternatives, or optionality when their inputs are absent. `CHECKED` records the analyst's challenge, not proof of no bias. A blank or generic assertion such as “looks good” is invalid. Unresolved flags remain visible and make `judgment_status: HUMAN_REVIEW_REQUIRED`.

## Result and failure behavior

The frozen report binds the packet hash, 05 report ID, metric IDs and selected filing/source versions, model-file digest, calculation version, entity, security, cutoff, run ID, computed value and range, diagnostics, named gap reasons, and `publication_allowed: false`. Its `analysis_status` is `CALCULATED_MODEL_UNVERIFIED` only when every required reference and arithmetic check passes. Unavailable typed evidence freezes `BLOCKED_EVIDENCE` with no complete fair value. Malformed inputs, inconsistent cutoff or identity, and invalid arithmetic raise before writing a report. `judgment_status` is always `HUMAN_REVIEW_REQUIRED` in this slice, even if every field is filled. Structured diagnostic statuses cannot be promoted to factor scores, evidence grade A, high conviction, or a trading stance.

The report is written atomically and append-only under `state/analysis_runs/<run_id>.json`. An identical invocation returns the same report after rechecking parents and current bytes. Changed inputs under one run ID fail. A new revision uses a new ID and links the previous report; it cannot overwrite a thesis or fair value. Failed validation leaves no success report. A deterministic blocked report may be frozen for a valid packet with unavailable evidence, but syntax errors and broken report bindings raise before write.

## Acceptance and limits

- Synthetic successful calculation proves only contract mechanics; blocked evidence, late metric, restatement, damaged model/source, tampered parent, invalid probability/range, duplicate debate value, and changed replay must be tested.
- The result is an internal worksheet. No live company decision, published stance, case opening, or rank is implied.
- Model correctness, human causal judgment, bias removal, independence, full-corpus contradiction discovery, and valuation calibration remain unverified. Mini spec 09 checks whole-snapshot integrity; 12 requires historical evidence and explicit promotion.
- The Framework's mandatory complete company output remains a target. This slice records exactly which parts are `NOT_ASSESSED` instead of claiming full compliance.
